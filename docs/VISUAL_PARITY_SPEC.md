# VisualParitySpec · 1:1 视觉对齐规范

> `VisualParitySpec` 是**版本化、按引擎分别维护**的对齐清单。它是「画面 1:1 还原」这一硬验收的结构化表达，不是一句口号。

## 数据结构

```kotlin
data class VisualParitySpec(
    val version: String,                          // spec 版本号
    val edition: Edition,                         // JAVA / BEDROCK —— 各自一份，禁止通吃
    val dimensions: Map<ParityDimension, DimensionBaseline>,
    val resourcePackHash: String,                 // 资源包哈希
    val provenance: Provenance,                   // 来源 / 待验证 / 授权凭证
)
```

- `ParityDimension`：8 个对齐维度，见下表。
- `DimensionBaseline`：`description`（基线描述）+ `status`（VERIFIED / PENDING_VERIFICATION）。
- `Provenance`：`source`（来源）、`pendingVerification`（是否待验证）、`authorizationCredentialId`（路径 B 的凭证编号，路径 A 为 null）。

## 8 个对齐维度（逐项版本化）

| # | 维度 | 对齐要点 | 典型核对方法 |
|---|---|---|---|
| 1 | 方块与贴图 | 像素网格结构与分辨率、调色板、面贴图差异；玻璃/叶片/水/冰透明与半透明；流动/脉动动画；破坏裂纹叠加；物品栏图标 | 并排截图、调色板比对、动画关键帧 |
| 2 | 世界几何 | 区块网格与分段、面剔除与遮挡、顶点 AO、方块边缘与深度；天空盒、云层、日月轨迹；雾随视距衰减与地平线过渡 | 雾衰减曲线、几何分段一致性 |
| 3 | 光照 | 天空光 + 方块光双通道、光照等级到顶点亮度映射、传播更新在画面可见（火把/洞口/昼夜）、平滑光照版本差异 | 昼夜亮度曲线、火把点亮前后差异 |
| 4 | 生物群系 | 地形轮廓与高度分布、草/叶/水/雪/沙按群系渐变、过渡带、植被密度与结构 | 群系配色采样、过渡带截图 |
| 5 | 实体与动画 | 外形比例与部件层级、行走/摆臂/头转/受伤闪红、掉落物旋转、破坏放置反馈、粒子、盔甲与手持挂载 | 逐帧差异、动画时序 |
| 6 | 流体与红石可见性 | 流体流动与液面高度、红石粉充能亮度与走向、活塞/方块更新即时反馈——与运算层真实状态同步 | 状态→画面同步校验 |
| 7 | UI/HUD 视觉 | 字体与字重、准星、热键栏、调试信息排布、菜单配色与边角；本 App HUD 风格协调 | 布局对照 |
| 8 | 版本差异分别对齐 | Java 与 Bedrock 在叶片透明、天空光照平滑、雾、实体渲染、VSync 观感上分别还原 | 两份独立 spec 交叉核对 |

## 实时性硬约束

- 每帧由渲染层根据引擎**当帧**世界状态生成；区块重建、光照更新、红石与实体状态变化必须在画面可见。
- **禁止**：视频回放、截图轮播、预录帧序列、静态壁纸、占位色块、循环动画贴图冒充世界变化、画面与负载解耦成两套驱动。
- 切换 `AssetPack`（路径 A ↔ B）**只替换资源，不改变世界状态与工作量计数**；同种子同参数下 tick / 区块 / 实体计数零差。

## 校验与门禁

- `provenance` 对公开资料不足的细粒度参数一律标 `待验证`，不宣称官方数值。
- 开发期用**参照素材**做 1:1 比对，参照素材只在开发期、不进发布包（见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3 节）。
- CI 视觉回归门禁：Spec 版本或资源包哈希变化必须重跑对齐清单，未通过不允许出包。

## 资产路径

- **路径 A**：按公开可观测视觉规范独立重绘，资源全部自产，带创作记录（`app/src/main/assets/packA/CREATION_LOG.md`）。
- **路径 B**：`AssetPack` 接口加载官方资源包，**仅当构建环境持有书面授权凭证时启用**，凭证写入 `system.json`。
