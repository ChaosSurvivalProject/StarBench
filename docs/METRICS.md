# 指标定义

> 所有指标**按引擎分别计算**，Java 与 Bedrock 各一套完整表格；再给一张并排对比页，但**不出合并总分**。写进代码注释与报告。

| 指标 | 定义 | 备注 |
|---|---|---|
| **峰值性能** | 全程未触发温控降频的窗口内，取最佳连续窗口（如 60s）的平均 FPS / 最低 tick ms / 最高区块吞吐；标注窗口温度与均频 | 禁止拿冷机第一帧当峰值 |
| **平均（持续）性能** | 热身结束后正式期全程的**调和平均 FPS**、平均帧时间、平均 tick ms；标注热稳态温度与均频 | 调和平均避免高帧样本稀释卡顿 |
| **1% Low** | 所有帧生成时间降序取最慢 1% 样本的平均，换算 FPS | 与平均分开计分 |
| **0.1% Low** | 同上取最慢 0.1% | 反映极端卡顿 |
| **p99 帧时间** | 帧生成时间 99 分位 | 尖刺信号 |
| **Jank 率** | 超过 2×目标帧预算的帧占比 | 稳定性指标 |
| **温控跌幅** | `(峰值 − 持续) / 峰值 × 100%` | 附频率曲线与热状态时间线，作为改进意见一级依据 |
| **avg / max MSPT** | 平均 / 最大每 Tick 毫秒 | tick 侧 |
| **longest tick** | 最长单 tick | 「最长 tick 才是玩家真正感到的卡顿」 |
| **区块重建耗时 / 实体 tick 耗时** | 分项耗时 | 定位瓶颈 |
| **帧时间曲线** | 逐帧序列，含尖峰 | ASCII 图进 Markdown 报告 |

## 采集可得性规则

- GPU counters 名称按设备**精确匹配**并先读 descriptor；GPU 频率 ≠ 利用率。
- battery current 是整机口径，大量设备返回 0 时标 `unavailable` 并**重新分配权重**。
- 采集失败一律标 `unavailable`，从权重中剔除，报告注明原因；**禁止填 0 或估算值冒充实测**。

## 报告附带元信息

- `VisualParitySpec` 版本、`AssetPack` 模式（A / B）、资源包哈希——便于跨次比对确认画面口径一致。
- `system.json`：机型、系统、GPU vendor/renderer、引擎版本、规则包版本、Spec 版本、AssetPack 模式与哈希、授权凭证编号（若适用）、种子。
