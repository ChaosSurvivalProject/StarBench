# 授权前置检查表（发布门禁）

> 这是 **CI 发布侧门禁**，不是玩家侧操作。任何产出物发布前逐项核对；未通过则**不得出包**。

## 一、通用红线（所有发布形态，无授权时也必须满足）

| # | 检查项 | 无授权时要求 |
|---|---|---|
| 1 | 官方代码（反编译 / 借鉴原版源码） | 不得包含 |
| 2 | 官方贴图 / 模型 / 音效 / 字体资源文件 | 不得包含 |
| 3 | 官方商标、Logo、官方配色标识 | 不得包含，不得作品牌标识 |
| 4 | 对官方客户端的依赖 | 不得有 |
| 5 | 官方协议与认证服务的对接 / 调用 | 不得有 |
| 6 | 开发期 1:1 比对用的参照素材 | 不得进发布包 |
| 7 | 非官方声明 | **必须保留**（启动页 / 关于页 / 报告页） |
| 8 | 「我的世界」表述 | 仅描述性指代，非商标式使用 |
| 9 | 改进意见文案 | 不得建议改用官方客户端或获取官方资源 |

## 二、按资产模式分支

### 路径 A（默认，clean-room）

- [x] 所有资源自产，带创作记录 `assets/packA/CREATION_LOG.md`。
- [x] 非官方声明按路径 A 文案显示。
- [x] `system.json` 中 `assetPackMode = "A"`，`authorizationCredentialId = null`。
- [x] 画面按公开视觉规范 1:1 对齐，`VisualParitySpec.provenance.pendingVerification` 如实标注。
- **结论：满足以上即可无条件发布。**

### 路径 B（官方授权资源包）

- [ ] 持有 Mojang / Microsoft **书面授权**（文件归档于构建环境，编号可追溯）。
- [ ] 授权凭证编号写入 `system.json.authorizationCredentialId` 与构建产物。
- [ ] 合规文案与授权协议**逐字一致**，不超出授权范围表述。
- [ ] 授权资源包哈希与 `VisualParitySpec.resourcePackHash` 一致。
- [ ] 授权范围之外的资源已排除。
- **未满足任一 → 禁止以路径 B 出包，回退路径 A。**

## 三、模组 / 自定义资源包

- [ ] 第三方 `AssetPack` 过与路径 B **相同**的授权凭证校验。
- [ ] 未授权模块只允许包含模块自产资源，不破坏 `VisualParitySpec` 基线（否则标「视觉对齐未通过」）。
- [ ] 模块崩溃不阻断主跑分，仅标该模块结果无效。

## 四、CI 门禁动作（实现期接入）

- 扫描 release APK/AAB 的资源表与文件清单，命中官方资产特征 → **fail build**。
- 校验 `system.json`：模式 A 时凭证必须为空；模式 B 时凭证必须存在且匹配归档。
- 校验合规声明字符串存在且与模式匹配。
- 校验 `VisualParitySpec` 版本 / 资源包哈希变更后视觉回归清单已重跑通过。

> 提示：本检查表是工程约束，不构成法律意见。实际授权范围以与 Mojang / Microsoft 签署的书面协议为准。
