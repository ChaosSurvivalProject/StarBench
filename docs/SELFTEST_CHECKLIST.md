# 验收自测清单

> 对照需求提示词**第十二节**验收标准。骨架阶段可执行静态检查；运行时项在引擎 / 渲染实现完成后逐条打勾。

## 运行验收（12 条）

- [ ] 1. 冷启动后**只点一次**，无需任何后续操作即产出完整双引擎报告与改进意见。
- [ ] 2. 跑分全程屏幕有逐帧实时、按 `VisualParitySpec` 逐项比对通过的 1:1 还原画面与 HUD；非黑屏 / 静态图 / 视频回放 / 截图轮播 / 预录帧 / 占位色块。Java 与 Bedrock 画面分别对齐各自版本。
- [ ] 3. 报告同时含峰值、平均、1% Low、0.1% Low、p99、Jank 率、温控跌幅，且 Java / Bedrock 各一套、**无合并总分**。
- [ ] 4. 所有负载可重放：同种子同参数**工作量计数零差**；perfetto 实测与自报帧时间偏差 <15%。
- [ ] 5. 把设备加热 / 制造后台负载后重跑，温控跌幅与改进意见能随之变化（证明不是写死结论）。
- [ ] 6. 安装第三方负载模块后其场景出现在矩阵并可被计分；卸载 / 签名校验失败时主流程不受影响。
- [ ] 7. 启动页与报告页均可见温度告知与合规声明；发布包内**无未授权**官方代码 / 资源 / 商标 / 协议实现 / 认证调用；路径 B 构建产物含授权凭证记录。
- [ ] 8. 采集失败项标 `unavailable` 并重分配权重，无伪造数值。
- [ ] 9. 切换 `AssetPack`（A ↔ B）前后，同种子同参数工作量计数零差，证明画面资源未改变负载真实性。
- [ ] 10. `VisualParitySpec` 版本或资源包哈希变更后 CI 视觉回归门禁生效，未通过不允许出包。
- [ ] 11. HUD 可一键收起但**不影响数据采集**；收起后画面仍逐帧实时渲染。
- [ ] 12. 冷却判定：两套引擎之间未回到可接受热状态时记录「未完全冷却」并继续，不打断「点一下」。

## 骨架阶段静态检查（现在可执行）

- [x] 双引擎各自实现 `EditionEngine` 六个方法，无共享逻辑实现。
- [x] Java / Bedrock 各有一份 `VisualParitySpec`，`edition` 字段区分。
- [x] `ScoreCard` 含峰值 / 平均 / 1% Low 三个独立字段，无 `combinedScore`。
- [x] 报告层导出 Markdown / JSON / CSV / system.json 四种格式。
- [x] 采集失败项以 `unavailable` 枚举值表达。
- [x] 授权门禁 `AuthorizationGate` 在构造层阻止无凭证的路径 B 发布。
- [x] 渲染层接口只接受 `WorldSnapshot`，无视频 / 图片 / 预录帧入口。
- [x] 启动页常驻温度告知卡与两种资产模式的合规文案齐备。
- [ ] Gradle 工程在配置好 Android SDK 后 `:app:assembleDebug` 通过（依赖本地 SDK）。
- [ ] CI 门禁脚本接入（见 `.github/workflows/`，实现期补齐）。

## 自测方法提示

- **工作量零差**：同种子跑两次，比对 `RunMetrics.workloadCounters` 的每个字段；A/B 资源切换后重跑比对。
- **温控灵敏度**：先用风扇 / 冰袋冷却跑一轮，再连续高负载跑到热稳态跑一轮，比对 `thermalDrop` 与建议文本是否变化。
- **插件健壮性**：装一个签名错误的模块，确认主流程不中断、该模块结果标无效。
- **画面实时性**：抓相邻帧 `WorldSnapshot`，校验 `tickIndex` 递增且状态哈希变化。
